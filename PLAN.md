# План проекта: музыкальный плеер для Obsidian

## 1. Цель и пользовательский сценарий

Пользователь указывает папки с музыкой или добавляет отдельные файлы, запускает индексацию, собирает плейлисты и управляет воспроизведением из панели Obsidian. Исходные композиции остаются на диске и не перемещаются. Отдельно можно добавить URL YouTube и правило, которое включает заданный короткий звук после изменения задачи на выполненную.

## 2. Предлагаемый интерфейс

- Иконка плагина в левой панели открывает выделенный докуемый вид «Плеер». В нём размещаются транспортные кнопки, название, выбранный плейлист и список треков. Полноценные кнопки неудобно размещать только в строке состояния Obsidian.
- Неподвижное название в панели ограничивается 40 символами с пробелами и завершается многоточием. При включённой прокрутке отображается полное название в непрерывной бегущей строке. Нажатие показывает полное название и позицию в списке; в списке текущий трек подсвечивается.
- Кнопки: предыдущий, воспроизведение/пауза, остановка, следующий, список. Пока идёт воспроизведение, кнопка запуска отображает паузу; при паузе — воспроизведение.
- Рядом с транспортными кнопками находится выбор режима очереди: подряд (однократное прохождение), повтор очереди целиком или случайный трек. В случайном режиме после завершения выбирается следующий случайный трек; если в очереди больше одного элемента, текущий не повторяется сразу.
- Несколько плейлистов можно объединить в именованную коллекцию воспроизведения. Её очередь проходит включённые плейлисты по заданному порядку без ручной паузы между ними. Переключатель плейлиста исключает его треки из очереди, но сам плейлист и его состояние остаются видны в коллекции.
- Значок громкости открывает горизонтальный ползунок, который закрывается при клике вне него. Громкость и выбранная палитра сохраняются. Под кнопками отображаются анимированные столбики, перемотка, прослушанное и оставшееся время и длительность трека.
- Каталог содержит секции локальных треков, плейлистов и онлайн-ссылок. Удаление трека или плейлиста подтверждается в интерфейсе и не удаляет файл.
- Настройки включают источники, ручную индексацию, основной плейлист, автозапуск последнего трека, прокрутку названия, светлую/тёмную тему плеера, палитру кнопок, язык интерфейса и правила звуков действий.
- YouTube полностью отключён по умолчанию: первая установка работает только с локальной библиотекой. Пока пользователь не включит настройку, нет команды добавления YouTube-ссылки, онлайн-раздела и загрузки IFrame API.
- После явного включения YouTube появляется онлайн-раздел и отдельный переключатель автоматического возврата к последнему локальному треку при ошибке.
- Язык интерфейса выбирается вручную: русский, украинский или английский. Начальное значение — русский; все подписи, настройки, уведомления и сообщения об ошибках локализуются.
- Нажатие на название YouTube-трека, Play или значок глаза открывает встроенный плеер. Плеер остаётся видимым до закрытия пользователем; закрытие ставит YouTube на паузу.

## 3. Техническая архитектура

### Плеер

- `PlaybackController` управляет текущим треком, очередью, переходами и единой громкостью.
- Контроллер поддерживает три режима: однократное последовательное воспроизведение, повтор всей текущей очереди и случайный выбор следующего трека.
- Активная очередь строится как конкатенация треков включённых плейлистов выбранной коллекции; порядок плейлистов и треков сохраняется. Отключённые плейлисты остаются показаны в коллекции, но не попадают в очередь.
- Переход к следующему треку запускается автоматически, без нажатия пользователя. Точное бесшовное соединение звуковых данных двух файлов не обещается до отдельной проверки аудиобэкенда.
- Встроенный HTML Audio использует MP3/MPEG, WAV, Ogg/OGA/Opus, FLAC, AAC, CAF, M4A/M4B, аудиодорожки MP4/WebM и E-AC-3, если `canPlayType` сообщает о поддержке. Сторонние медиабиблиотеки не загружаются.
- `YouTubeBackend` управляет официальным IFrame Player API. ID извлекается из URL форматов `youtube.com/watch`, `youtu.be`, `youtube.com/shorts` и `music.youtube.com`.
- IFrame API загружается только после включения YouTube пользователем и первого просмотра/запуска ссылки. При выключенной настройке YouTube-контент скрыт и не обрабатывается.
- Контроллер запоминает последний локальный трек, который действительно начал играть в текущей очереди.
- При ошибке, запрете встраивания или блокировке воспроизведения плеер предлагает вернуться к последнему локальному треку из очереди. Если настройка автоматического переключения включена, переключается на него без дополнительного шага.
- Если в текущей очереди ещё не проигрывался локальный трек либо этот трек уже недоступен/исключён из очереди, автоматический режим не выбирает случайный файл: плеер показывает ошибку и предлагает выбрать локальную композицию.
- YouTube-плеер не прячется во время активного воспроизведения. Нельзя создавать фоновое воспроизведение, когда сам плеер скрыт от пользователя.

### Библиотека и состояние

- `LibraryIndexer` индексирует папки внутри vault, внешние папки и вручную добавленные файлы по расширениям `.mp3` и `.wav`.
- `LibraryRepository` хранит настройки, источники, элементы индекса, исключённые записи, плейлисты и ссылки в данных плагина через API Obsidian.
- Плейлист содержит ссылки на записи индекса, а не копии файлов. Один трек может входить в несколько плейлистов.
- Исключённые пользователем треки сохраняются как исключения, чтобы повторная индексация не добавила их обратно автоматически. Повторное добавление выполняется явно.
- Для файлов внутри хранилища использовать API Vault. Для внешних путей использовать нативный диалог выбора папки/файла и адаптер файловой системы desktop-приложения.
- Сохранять путь к источнику, читать оригинал для воспроизведения; не копировать, не перемещать, не переименовывать и не переписывать аудиофайлы.
- Целевые ОС: Windows, macOS и Linux. Мобильная совместимость не входит в требования; в манифесте плагина указать режим desktop-only.

### Панель и настройки

- Выделенный `ItemView` для плеера; настройки через `PluginSettingTab`.
- Команды Obsidian: открыть плеер, добавить файл/папку, переиндексировать, воспроизвести/поставить на паузу, остановить.
- Палитры реализовать через CSS-переменные, чтобы состояние кнопок было различимо при разных темах Obsidian.
- События DOM и Obsidian регистрировать с управлением жизненным циклом плагина, чтобы закрытый плагин не оставлял активный звук, таймеры или подписки.

### Звук при выполнении задачи

- Начальный вариант: правило «Markdown-задача изменилась с незавершённой на выполненную».
- Встроенные события первой версии: создание новой заметки и переход Markdown-чекбокса задачи из незавершённого в выполненное состояние.
- Сервис отслеживает доступные события Obsidian и запускает назначенный локальный файл. На первоначальной загрузке vault звуки не запускаются.
- Для каждого события пользователь выбирает синтезируемый пресет или локальный аудиофайл в формате, поддерживаемом HTML Audio, и включает или отключает правило.
- Для нажатия на чекбокс задачи звук запускается непосредственно при изменении состояния чекбокса; последующее событие обновления заметки не должно повторять сигнал.
- Встроенные сигналы генерируются Web Audio API и включают 15 вариантов; плагину не нужны системные звуковые файлы или внешние загрузки.
- Дополнительно предусмотреть ручные правила на основе поддерживаемых событий vault (например, создание, переименование или изменение заметки) и условий, заданных пользователем.
- При новом событии уже играющий сигнал прерывается, а новый запускается с начала. Срабатывания не ставятся в очередь.

## 4. Данные проекта

Предварительная модель данных:

```ts
interface LibrarySource {
  id: string;
  kind: "vault-folder" | "vault-file" | "external-folder" | "external-file";
  path: string;
  enabled: boolean;
}

interface LocalTrack {
  id: string;
  path: string;
  title: string;
  sourceId: string;
  format: "mp3" | "wav" | "ogg" | "oga" | "opus" | "flac" | "m4a" | "aac";
}

interface Playlist {
  id: string;
  name: string;
  trackIds: string[];
}

interface OnlineTrack {
  id: string;
  videoId: string;
  title?: string;
}

interface PlaybackCollection {
  id: string;
  name: string;
  playlists: Array<{
    playlistId: string;
    enabled: boolean;
  }>;
}
```

Отдельные настройки плагина хранят коллекции воспроизведения и порядок плейлистов в них, режим очереди, выбранную коллекцию, последний локальный трек, выбранный язык, включён ли автозапуск последнего трека, включено ли YouTube (по умолчанию `false`), включено ли автоматическое переключение YouTube на последний локальный трек (по умолчанию `false`), палитру, путь к созданной инструкции и правила звуков действий.
Отдельный список исключений хранит удалённые из индекса пути/идентификаторы, чтобы сканирование не добавляло их повторно.

Схема будет версионироваться для безопасного обновления сохранённых настроек. Для несуществующего или перемещённого файла плеер покажет понятную ошибку и предложит переиндексацию.

## 5. Этапы разработки

### Этап 0 — уточнение границ и короткие технические проверки

1. Подтверждено: поддержать папки в vault и внешние папки/файлы на Windows, macOS и Linux; пути использовать только для чтения и воспроизведения.
2. Проверить нативный выбор папки/файла и корректное чтение внешнего аудио на каждой целевой ОС.
3. Проверить встроенный YouTube-плеер в Obsidian, открытие только по нажатию, минимальный размер и поведение при потере сети.
4. Проверить ошибку YouTube и fallback на последний доступный локальный трек текущей очереди, включая отсутствие такого трека.
5. Для ручных правил зафиксировать перечень событий Obsidian, доступных через публичный API.

### Этап 1 — каркас плагина

1. Создать TypeScript-проект с `manifest.json`, точкой входа, сборкой и стилями.
2. Определить ID плагина и минимальную версию Obsidian; включить desktop-only режим.
3. Зарегистрировать докуемую панель, страницу настроек и базовые команды.
4. Добавить версию схемы, сохранение настроек и выбор языка RU/UK/EN.
5. При первой установке создать и открыть один Markdown-гайд на трёх языках в корне vault; запомнить путь, не перезаписывать существующие заметки.

### Этап 2 — каталог и плейлисты

1. Реализовать воспроизведение всех форматов, поддерживаемых HTML Audio, а также последовательное воспроизведение, предыдущий/следующий трек и play/pause/stop.
2. Индексировать локальные аудиофайлы по расширениям, которые поддерживает HTML Audio, не читая аудиофайлы при индексации.
3. Показать локальные треки и папки; обработать исчезнувшие пути.
4. Создать, переименовать и удалить плейлист; включать треки из разных папок.
5. Удалять элементы из индекса без физического удаления исходников и сохранять исключения между сканированиями.

### Этап 3 — базовое аудио и интерфейс управления

1. Реализовать воспроизведение всех форматов, поддерживаемых HTML Audio, а также последовательное воспроизведение, предыдущий/следующий трек и play/pause/stop.
2. Синхронизировать состояние кнопки с фактическим состоянием проигрывателя.
3. Добавить горизонтальный ползунок громкости и запоминание уровня.
4. Ограничить строку 40 символами; показывать полное название и номер трека при нажатии.
5. Добавить прокрутку названия с переключателем в настройках.
6. Реализовать яркую палитру по умолчанию и несколько доступных пользователю цветовых схем.

### Этап 4 — YouTube

1. Принимать полный URL, проверять домен и извлекать ID видео.
2. Показывать миниатюру до запуска; открывать видимый официальный встроенный плеер нажатием на название трека, Play или значок глаза.
3. Управлять play/pause/stop и очередью через YouTube IFrame API.
4. Не извлекать аудио отдельно от YouTube-плеера и не маскировать/скрывать его обязательный интерфейс. При активном воспроизведении плеер остаётся видимым даже после ухода курсора.
5. Скрывать онлайн-секцию при `offline`-состоянии и показывать понятную ошибку, если подключение к YouTube недоступно при формально активной сети.
6. При ошибке предложить последний проигрывавшийся локальный трек из активной очереди; при включённой настройке автоматического переключения начать его без дополнительного шага.
7. Описать сетевые обращения и ограничения онлайн-воспроизведения в README плагина.

### Этап 5 — сигналы действий и задач

1. Добавить управление правилами «событие → локальный файл».
2. Включить встроенные правила для создания заметки и завершения Markdown-задачи.
3. Добавить редактор ручных правил на базе поддерживаемых событий Obsidian.
4. Не запускать событие на начальной загрузке vault. Каждое новое событие прерывает текущий сигнал и запускает назначенный звук с начала.
5. Добавить проверку выбранного файла и переключатель включения правила.

### Этап 6 — подготовка к использованию

1. Обработать повреждённые настройки, недоступные файлы, неподдерживаемые форматы и ошибки сети.
2. Зафиксировать ограничения по платформам, встроенным аудиоформатам и YouTube.
3. Подготовить README для установки вручную, описание сетевого доступа и локализаций.
4. Провести ручную проверку сценариев на выбранных версиях Obsidian и Windows/macOS/Linux перед выпуском.

## 6. Критерии готовности первой версии

- MP3 и WAV из vault и внешних папок запускаются, ставятся на паузу, продолжаются и останавливаются с панели.
- Плагин работает на Windows/macOS/Linux; файлы только читаются для воспроизведения и не копируются, не перемещаются, не переименовываются и не переписываются.
- Папки можно добавить и индексировать повторно; отдельные треки и плейлисты управляются без удаления файлов с диска.
- Треки из нескольких источников можно включить в один плейлист, а несколько плейлистов — в одну коллекцию воспроизведения.
- Отключённый плейлист исключается из собранной очереди, но остаётся видимым в коллекции и может быть снова включён.
- Режим очереди переключается между однократным последовательным воспроизведением, повтором всей очереди и случайным выбором следующего трека.
- Отображение кнопки и название трека соответствуют текущему состоянию плеера; громкость настраивается горизонтальным ползунком.
- Ссылка YouTube принимается только после проверки URL; нажатие открывает официальный видимый плеер, который остаётся видимым во время воспроизведения.
- При ошибке YouTube пользователь может переключиться на последний проигрывавшийся локальный трек текущей очереди; отдельная настройка включает автоматическое переключение.
- Интерфейс доступен на русском, украинском и английском.
- Пользователь может привязать звук к созданию заметки, отметке задачи как выполненной и ручным правилам; новое срабатывание прерывает предыдущий звук.
- Автозапуск последнего трека доступен в настройках и выключен по умолчанию.
- YouTube выключен в настройках по умолчанию; до ручного включения плеер работает только с локальными файлами.
- При первой установке Markdown-инструкция на русском, украинском и английском языках создаётся в корне vault и открывается один раз. Если имя занято, плагин создаёт файл с суффиксом, не переписывая существующую заметку.
- Параметры, плейлисты, источники и исключения сохраняются после перезапуска Obsidian.

## 7. Подтверждённые решения и ограничения

Ответы пользователя определят окончательную архитектуру и объём первой версии.

1. **Подтверждено:** поддержать vault и внешние папки, только чтение; целевые платформы — Windows/macOS/Linux.
2. **Подтверждено:** YouTube через официальный embed с превью; на ошибке предложить последний проигрывавшийся локальный трек из активной очереди; автоматическое переключение — отдельная настройка.
3. **Подтверждено:** интерфейс на русском, украинском и английском; автозапуск последнего трека доступен, но по умолчанию выключен.
4. **Подтверждено:** начальные звуковые события — создание заметки и выполнение задачи; предусмотреть ручные правила. Новое событие прерывает предыдущий сигнал.
5. **Ограничение интерфейса YouTube:** встроенный плеер открывается нажатием и остаётся видимым, пока играет видео: YouTube запрещает фоновые плееры, скрытые от пользователя. Плеер также должен иметь минимальную область отображения 200×200 px.

README описывает мини-плеер в строке состояния и говорит, что YouTube-видео загружаются в фоне. Исходный код создаёт YouTube IFrame внутри элемента статусной панели и отдельно создаёт HTML Audio для локальной музыки. В режиме локальной музыки YouTube-плеер ставится на паузу и скрывается CSS-классом; для режимов YouTube этот класс снимается.

Это полезный пример разделения YouTube- и локального аудиобэкендов, но не подтверждение того, что скрытое воспроизведение соответствует актуальным требованиям YouTube. В просмотренном коде iframe задаётся размером 200×100 px и с отключёнными элементами управления; для нового плагина закладывается видимая область плеера не меньше 200×200 px и отсутствие скрытого воспроизведения. Отдельного режима, где обложка показывается только при выборе трека, в README и проверенном участке реализации не обнаружено.
